# BlitzMD extensions

Examples for behaviour beyond the GFM spec (GitHub rendering details that
BlitzMD reproduces). Run with `mdview_test spec tests/spec/mdview-extensions.txt --strict`.

## Front matter

YAML front matter at the very top of a file is shown as a two-column table,
one row per top-level key (key in bold, then its value). GitHub puts the keys
side by side as columns instead; BlitzMD reads top to bottom and never needs
horizontal scrolling for it.

```````````````````````````````` example
---
title: Hello
layout: post
---

# Hi
.
<table><tbody>
<tr><th align="left">title</th><td>Hello</td></tr>
<tr><th align="left">layout</th><td>post</td></tr>
</tbody></table>
<h1>Hi</h1>
````````````````````````````````

Quoted strings keep their colons. Short plain lists are joined with commas;
a list with an item containing a comma gets one item per line.

```````````````````````````````` example
---
title: "Part 2: the sequel"
tags: [a, b, c]
pairs: [a, 'b, c', d]
---
.
<table><tbody>
<tr><th align="left">title</th><td>Part 2: the sequel</td></tr>
<tr><th align="left">tags</th><td>a, b, c</td></tr>
<tr><th align="left">pairs</th><td><p>a</p><p>b, c</p><p>d</p></td></tr>
</tbody></table>
````````````````````````````````

Block sequences, nested mappings (nested key/value tables), comments and
empty values.

```````````````````````````````` example
---
# a comment
authors:
  - name: Ann
    role: dev
  - Bob
meta:
  draft: true
empty:
---
.
<table><tbody>
<tr><th align="left">authors</th><td>
<table><tbody><tr><th align="left">name</th><td>Ann</td></tr><tr><th align="left">role</th><td>dev</td></tr></tbody></table>
<p>Bob</p>
</td></tr>
<tr><th align="left">meta</th><td><table><tbody><tr><th align="left">draft</th><td>true</td></tr></tbody></table></td></tr>
<tr><th align="left">empty</th><td></td></tr>
</tbody></table>
````````````````````````````````

A sequence at the same indentation as its key.

```````````````````````````````` example
---
list:
- one
- two
---
.
<table><tbody><tr><th align="left">list</th><td>one, two</td></tr></tbody></table>
````````````````````````````````

Block scalars: literal keeps line breaks, folded joins lines.

```````````````````````````````` example
---
literal: |
  line one
  line two
folded: >
  joined
  words
---
.
<table><tbody>
<tr><th align="left">literal</th><td>line one<br />line two</td></tr>
<tr><th align="left">folded</th><td>joined words</td></tr>
</tbody></table>
````````````````````````````````

Special characters are text, not HTML.

```````````````````````````````` example
---
formula: a < b & c > d
---
.
<table><tbody><tr><th align="left">formula</th><td>a &lt; b &amp; c &gt; d</td></tr></tbody></table>
````````````````````````````````

YAML beyond the supported subset is shown as a code block.

```````````````````````````````` example
---
base: &anchor
  x: 1
copy: *anchor
---
.
<pre><code class="language-yaml">base: &amp;anchor
  x: 1
copy: *anchor
</code></pre>
````````````````````````````````

Without a closing delimiter it is ordinary Markdown.

```````````````````````````````` example
---
title: x
.
<hr />
<p>title: x</p>
````````````````````````````````

Only at the very start of the file.

```````````````````````````````` example
Text

---
title: x
---
.
<p>Text</p>
<hr />
<h2>title: x</h2>
````````````````````````````````

An empty block, or one that doesn't start like a mapping, is left to Markdown
(the GFM spec renders these as thematic breaks and setext headings).

```````````````````````````````` example
---
---
Text
.
<hr />
<hr />
<p>Text</p>
````````````````````````````````

```````````````````````````````` example
---
Foo
---
Bar
.
<hr />
<h2>Foo</h2>
<p>Bar</p>
````````````````````````````````

Four dashes are a thematic break, not front matter.

```````````````````````````````` example
----
title: x
---
.
<hr />
<h2>title: x</h2>
````````````````````````````````

## HTML lists

The start number of an HTML list is kept within nine digits, like a
Markdown list's, so the numbers of its items can't overflow.

```````````````````````````````` example
<ol start="2147483647"><li>a</li><li>b</li></ol>
.
<ol start="999999999">
<li>a</li>
<li>b</li>
</ol>
````````````````````````````````

## Raw HTML across lines

A tag may go on over the next lines of a paragraph, as READMEs often do
with long `<a>` and `<img>` tags (md4c reports it in pieces).

```````````````````````````````` example
See <a
href="https://e.com">here</a> now.

Logo <img src="x.png"
     width="50" alt="logo"> end

q <a href="#x"
   title="t">link
text</a> r
.
<p>See <a href="https://e.com">here</a> now.</p>
<p>Logo <img src="x.png" alt="logo" /> end</p>
<p>q <a href="#x" title="t">link text</a> r</p>
````````````````````````````````

## Footnotes with more blocks

Like GitHub, blocks indented by four spaces after a footnote definition
belong to the footnote.

```````````````````````````````` example
See[^1].

[^1]: first

    more of it
.
<p>See<a href="#fn-1" title="Footnote 1"><sup>1</sup></a>.</p>
<p>first</p>
<p>more of it <a href="#fnref-1-1" title="Back to reference 1">↩︎</a></p>
````````````````````````````````

A footnote defined in those blocks is one of the document's: numbered
after its own footnotes, it follows them.

```````````````````````````````` example
A[^a] B[^b].

[^a]: first

    more [^x]

    [^x]: nested

[^b]: second
.
<p>A<a href="#fn-1" title="Footnote 1"><sup>1</sup></a> B<a href="#fn-2" title="Footnote 2"><sup>2</sup></a>.</p>
<p>first</p>
<p>more <a href="#fn-3" title="Footnote 3"><sup>3</sup></a> <a href="#fnref-1-1" title="Back to reference 1">↩︎</a></p>
<p>second <a href="#fnref-2-1" title="Back to reference 1">↩︎</a></p>
<p>nested <a href="#fnref-3-1" title="Back to reference 1">↩︎</a></p>
````````````````````````````````

A line that only looks like a definition — the lazy continuation of a
paragraph — is text, and what follows it stays where it is.

```````````````````````````````` example
See[^1].

Paragraph line
[^1]: def?

    code block line
.
<p>See[^1].</p>
<p>Paragraph line [^1]: def?</p>
<pre><code>code block line
</code></pre>
````````````````````````````````

## Markdown loose in an HTML table

A Markdown block directly inside `<table>` or `<tr>` gets an implicit
cell, like HTML content there does.

```````````````````````````````` example
<table>
<tr>

**Paragraph directly in tr**

</tr>
</table>
.
<table>
<tbody>
<tr>
<td><p><strong>Paragraph directly in tr</strong></p>
</td>
</tr>
</tbody>
</table>
````````````````````````````````

## Stray list items

An `<li>` outside a list is drawn as a one-item list, which ends where
anything but another item follows.

```````````````````````````````` example
<li>one</li>
<li>two</li>

After.

<li>

**markdown in li**

</li>

Last.
.
<ul>
<li>one</li>
<li>two</li>
</ul>
<p>After.</p>
<ul>
<li><p><strong>markdown in li</strong></p>
</li>
</ul>
<p>Last.</p>
````````````````````````````````
